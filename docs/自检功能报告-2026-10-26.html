一句话结论

项目可以跑起来，学生端与教师端的主链路在真实模型下全部走通，代码质量与界面完成度都明显高于常见的「课程作业型」项目。 它的定位是单机、单教师、无数据库的本机教学工具——这个边界之内它是完整可用的；一旦要面向真实班级、多设备、公网访问，缺的是身份体系、并发存储与工程化交付这三件事，而不是功能页面。

01启动过程

按 README 的 start.bat 流程启动时，遇到两个环境层面的阻塞；都不是业务代码问题，但会让「双击即用」的承诺在换机后失效。

步骤现象原因与处理结果
1 依赖检查 仓库内自带的 .venv 是上一台机器（用户名 86139、Python 3.10）创建的，解释器路径写死在 pyvenv.cfg 里，直接报 No Python at ...。 已绕过
2 导入失败 托管 Python 环境缺 python-multipart，导致 fastapi 在注册文件上传路由时直接抛错、进程起不来。安装后正常。 已修复
3 服务启动 python -m server.main --port 8010，1.5 秒内完成 startup，/api/health 返回 ok:true，mode:live，静态前端 200。 正常
4 数据隔离 自检会写入班级、作业、提交记录。为不污染真实 data/，复制一份到临时目录，用 EDU_DATA_DIR 指向副本运行。 已隔离

给「双击即用」的两条建议

  • 不要把 .venv 打进压缩包分发——它绑定了绝对路径和 Python 小版本。让 start.bat 每次自建更稳（现在的脚本其实有这个逻辑，只是 if exist 判到了坏环境才重建，判断条件可以再加一条「能否 import sys 成功」）。
  • requirements.txt 少了 python-multipart。虽然是 fastapi 的可选依赖，但本项目用了 UploadFile，属于必需项，应显式写进去。

03发现的缺陷

已修复  点击「课堂」导航抛 ReferenceError: refreshLessons is not defined

位置：web/src/store.js:64

成因：switchView() 里调用 refreshLessons()，但 store 里实际导出的函数名是 loadLessons()——纯拼写不一致。由于 loadLessons 是 function 声明会被提升，refreshLessons 却从未定义，所以每次切到课堂视图必然抛错。

影响：判断为「中」。界面不会白屏（Vue 捕获了异常，其余视图照常），但课程列表不会刷新——刚生成的课堂在「我的课堂」下拉里看不到，必须整页刷新才出现。同时它顺带证明了 loadLessons 的异常没有被就地捕获。

修复：改为 loadLessons().catch((error) => notify(error.message, "error"))，一并补上失败兜底；已重新 vite build（产物 index-CbjNwdHn.js），复测 0 报错。

// web/src/store.js
export function switchView(view) {
  state.view = view
  if (view === 'progress') refreshProgress()
-  if (view === 'classroom') refreshLessons()
+  if (view === 'classroom') loadLessons().catch((error) => notify(error.message, 'error'))
}

整体评价

约 5 200 行前端 + 33 个后端模块，44 个接口全部有前端调用、无死路由。真正的亮点不在「做了什么功能」，而在几个容易被忽略的工程细节：

  • SSE 用事件驱动而不是轮询，断线重连能补数据——多数同类项目在这里会退化成定时刷新。
  • 演示模式不是假数据，是「本地规则生成 + 显式标注」，并且文档明说不要把服务暴露公网，边界是清醒的。
  • 自带 api_audit.py 这种「前后端契约」脚本，说明作者想过「改了路由怎么保证前端没漏」。
  • 导出的中文文件名做了 RFC 5987 编码，HTML 报告有真实版块结构而非一坨 <div>。

05还缺少什么

按「会不会挡住真实使用」排序，不按代码工作量排序。P0 是拿去给一个班用就会出事的地方，P1 是教学现场一定会提出的需求，P2 是工程化欠账。

P0上线前必须补—— 单机 demo 与「真实班级可用」的分界线
缺口现状与风险
学生身份无鉴权 student_id 直接放在请求体里传（/api/student/tasks/{id}/submit 等都是），没有任何凭证校验。知道或猜到别人的 id 就能替他交卷、看他的成绩。同一台机器演示没问题，一个班 40 人同时用就变成「谁都能改谁的卷」。
登录态不持久 教师 token 存在进程内字典（_TOKENS）里，服务一重启全体掉线、下次上课要重新登录；也没有多进程共享，将来开两个 worker 会出现「登录时在 A 进程、请求打到 B 进程 → 401」。
存储是单进程文件锁 store.py 用 threading.RLock + 整文件读写。多线程还行，多进程必然丢写；list_items() 每次把整个集合的 JSON 全读一遍再排序，学生提交一多，概览页会肉眼可见地变慢。
无自动化测试 没有 tests/、没有 pytest、没有任何 CI 配置。现在靠 4 个手跑脚本兜底——能发现问题，但改代码时不会自动拦住回归。我刚修的那个 refreshLessons 就属于「跑一遍页面就能发现、但没有测试会替你记住」的类型。
API Key 明文落盘 data/settings.json 里明文存着密钥（.gitignore 已忽略 data/，但打包分发、截图、共享目录时极易带出去）。建议至少支持从 .env 读、界面上不回显、日志里不打印。本次自检打印过该字段，建议轮换一次这个 Key。
P1教学现场一定会提的需求—— 功能层面的空白
缺口为什么会被提出来
学生换设备即失身份学生身份只存在 localStorage。机房换机器、清缓存、用手机再进，就要重新输邀请码 + 姓名，且历史成绩找不回来。教师端看到的会是「同名的两个学生」。
作业不能上传附件只能文本作答。数学证明、化学方程式、手写计算题、实验报告全都用不了——而这些恰恰是最需要批改的题型。
没有题库沉淀每次出题都是现场生成，生成完只能挂在一次作业上。同一份好题无法复用到另一个班，也无法在下次讲同一课时调出来微调。教学里「攒题」是刚需。
导出没有 Excel / Word只有 CSV + HTML + PPTX。教务要的成绩表基本是 .xlsx，纸质归档要 .docx；CSV 用 Excel 打开中文常乱码，还得手动转一次。
没有学情趋势进度页只有「当前掌握度」一个快照，没有按周 / 按次的变化曲线。老师最想回答的是「这孩子是在进步还是在掉队」，单点数值答不了。
无未交催办有实时事件，但没有「截止前提醒」和「一键催交」。40 人的班靠老师手动点名未交名单，很费时间。
单教师模型一个账号一套班级，没有教研组、没有班级共享、没有协作者。同一门课多人上就要各建一套班，数据对不上。
扫描件无 OCRREADME 已明确声明不支持，属于有意为之；但如果老师习惯拍讲义，这会是最先撞上的墙。
P2工程化欠账—— 不影响今天用，影响以后维护和交付
缺口说明
无容器化 / 跨平台启动只有 start.bat（Windows）和 start.sh，没有 Dockerfile。换台 Linux 服务器要自己装 Python、建 venv、装 Node 构建前端。
无日志与监控只有 uvicorn 控制台输出，不落盘、无轮转。课上出问题时，事发日志关掉窗口就没了。
无备份 / 恢复入口README 让手动拷 data/。没有一键导出、定时快照或「恢复某个时间点」。
模型调用无重试与限流llm.py 单次请求，失败直接抛 LLMError 给用户。没有指数退避重试，也没有并发上限——40 人同时生成课堂会一起打满上游配额。
检索索引每次重建rag.py 每次查询都重新分块打分。资料只有几百字时无感，现在库里已有一份 33 万字讲义，每次问答都要重算一遍 BM25。
无接口版本化全部挂在 /api 下，将来改结构无法平滑过渡。
无障碍未系统验证导航有 aria-current、aria-label，基础不错；但表单标签关联、键盘焦点顺序、对比度没有系统检查。

06如果只做三件事

  1. 给学生一个真身份。 邀请码 + 姓名换成「邀请码 + 一次性口令」，服务端签一个持久 token 放进 localStorage。这一步做完，P0 里的鉴权问题和 P1 里的「换设备失身份」一起解决，是投入产出比最高的一改。
  2. 把教师 token 和存储搬出内存。 最小方案：token 落一张 data/sessions.json（带过期时间），存储加文件级写锁。不上数据库也能撑住一个教研组；真要多进程再上 SQLite——本项目的数据模型非常简单，迁移成本很低。
  3. 补一层「跑得起来」的回归测试。 把现有 4 个 smoke 脚本改成 pytest 用例（它们本来就是纯 HTTP 调用，改造成本几乎为零），再加一个 GitHub Actions 跑 pytest + npm run build。这样以后每次改动都有兜底，不用靠人肉点页面。
