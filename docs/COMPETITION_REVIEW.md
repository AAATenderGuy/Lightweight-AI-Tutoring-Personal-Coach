# 竞赛评审意见：Edu（AI 创新大赛 · Agent 应用赛道）

> **评审对象**：Edu 轻量级 AI 教学服务 `v1.5.0`
> **评审视角**：AI 创新大赛评委 / 投资人口吻，按「创新性、Agent 技术含量、完成度、应用价值、商业与合规、展示」六维打分
> **评审日期**：2026-10-26
> **评审材料**：仓库代码（Python 38 文件 6029 行、Vue 18 文件 4910 行、JS 528 行）、README、docs/ 截图与评审报告、pytest 37 例、4 个冒烟脚本
> **先说明**：本文按"能拿奖"的标准写，不是按"能跑"的标准写。措辞会比较硬，但每条都给了代码位置和改法。

## 〇、评审假设（先对齐口径）

不同比赛、不同赛道的权重差别很大。本文按以下假设打分，若你的比赛口径不同，请按第七节的敏感性分析折算：

- 赛道：**AI 应用创新 / Agent 应用**（不是算法赛道，不要求 SOTA）
- 评审关注：**有没有真创新、Agent 是不是真 Agent、有没有效果证据、能不能落地、合不合规**
- 校赛规模：50–150 支队伍，应用赛道取前 10%–20% 获奖
- 区域赛/省赛规模：300–800 支队伍，决赛名额约前 15%–25%
- 团队：以学生为主，允许 1–5 人

## 一、一句话结论

**这是一个"完成度像优秀毕业设计、创新性像课程综合大作业"的项目。**

它最大的优点和最大的缺点其实是同一件事：**把所有力气都花在"把它做完整"上，而没有花在"证明它为什么新、为什么有效"上。**

评委看完 3 分钟演示会承认："做得真全，界面也干净。"
然后会问三个问题，而目前三个都答不好：

1. **"你的 Agent 在哪？"** —— 目前是"角色扮演 + 串行发言"，不是 Agent。
2. **"凭什么说它比现有工具好？"** —— 没有前后测、没有对照、没有用户数据。
3. **"学生教务密码你直接导进来？"** —— 合规上会被追问。

## 三、最致命的 8 个薄弱点

> 按"扣分权重 × 评委可见度"排序。每条给：评委看到什么 → 根因（代码证据）→ 扣多少 → 怎么改。

### W1 「Agent」名不副实，是最大扣分项

**评委看到**：演示里几个"小问、小理、小思"轮流说话，主持人"选人"。看起来像 Agent，但追问"它会不会自己调工具、自己纠错"就露馅。

**根因（代码证据）**：

- `server/services/group.py:45-93`：整场讨论只有**一次** `llm.json` 调用（主持人规划），之后每个角色一次 `llm.stream`（`server/api/classroom.py:173-209`），**没有工具调用、没有 ReAct 循环、没有记忆检索、没有反思/重试**。
- 角色"记忆"只是把最近 10 条对话拼进 prompt（`group.py:13-21`），没有向量记忆、没有共享黑板、没有结构化状态。
- `grep -i "tool_call|function_call|reflection|embedding|langgraph|autogen|crewai"` 在 `server/` 下**零命中**。

**扣分**：Agent 维度 25 分里至少扣 10 分。

**怎么改（P0，两周可做）**：
把"角色扮演"改成一条真正的 **教学诊断 Agent** 链路，评委一眼能看懂：

```text
目标：为一次作业生成"学情诊断报告"
工具（真实函数，不是 prompt）：
  search_materials(query)        -> 资料片段
  get_mastery(student_id)        -> 知识点掌握度
  list_wrong_questions(assignment_id) -> 错题
  generate_practice(points)      -> 变式题
  write_report(sections)         -> 落库
循环：plan -> call tool -> observe -> revise -> final
可观测：前端展示每一步的 tool 名、入参、耗时、结果摘要
```

产出物：一个"点一下、Agent 自己查 5 个工具、写出带证据链的诊断报告"的演示。**这是目前项目最缺、也最容易补出"Agent 感"的东西。**

### W2 创新是"集成"，不是"方法"

**评委看到**：README 自己写"把 DeepTutor 和 OpenMAIC 合成一个应用"。诚实是优点，但在创新赛道等于承认"没有新东西"。

**根因**：

- 掌握度是"最近 5 次加权 + 证据不足设上限"（`mastery.py:13-28`），属于常见做法；
- 检索是 BM25（`rag.py`），无向量、无 rerank、无混合检索；
- 课堂生成、出题、判分都是"调一次模型 + 解析 JSON"，没有新范式；
- 真正的自研点只有"零依赖 HTML 报告"（手写 CSS/SVG 图表）和"单进程零基础设施"，但这两点在答辩里很难被称为"AI 创新"。

**扣分**：创新性 25 分里扣 10 分。

**怎么改（P1）**：选一个点做到"可被引用"的程度，例如：

1. **教学闭环 Agent**：课堂讨论中暴露的误解 → 自动进入薄弱点 → 下一次作业默认覆盖 → 用前后测证明掌握度提升。这是别人没做的链路，故事性最强。
2. **可解释判分**：评分要点 → 证据句定位（引用学生原文的哪一句）→ 教师一键采纳/驳回。把"AI 判分"做成"可审计判分"。
3. **低成本自适应**：用掌握度 + 题目难度做在线选题（类似 Elo/IRT 的简化版），并做离线回放评估。

### W3 没有效果证据，应用价值只能靠嘴说

**评委看到**：功能很全，但"提升了多少分、省了老师多少时间、学生用了有没有效果"一个数字都没有。

**根因**：

- `tests/` 37 个用例全是工程测试（鉴权、CSV、判分边界），**没有教学效果评估**；
- `docs/` 只有界面截图，没有实验设计、没有前后测、没有用户访谈；
- 没有埋点/统计（除了提交率这种业务统计），没有"使用时长、完成率、正确率变化"的分析。

**扣分**：应用价值 15 分里扣 5 分，答辩时会被追着问。

**怎么改（P0，赛前必须补最小证据）**：

- **最小版本（3 天）**：找 1 个班（N≥20）做一次"AI 判分 vs 教师判分"一致性实验，报告 Pearson 相关 / 平均绝对误差；再记录教师批改耗时（人工 vs 系统）。
- **标准版本（2 周）**：两个班前后测（或一个班 A/B），报告 normalized gain，哪怕 N=40 也远胜"没有数据"。
- **加分版本**：SUS 可用性问卷 + 3 位教师访谈 + 1 所学校试用意向书。

> 评委不要求大样本，但要求"你有意识去证明"。零证据是硬伤，小样本是加分。

### W4 教学闭环没闭上，三份数据各过各的

**评委看到**：课堂、作业、掌握度三个模块都能用，但互相不"喂"。

**根因**：

- 课堂讨论不写掌握度（`group` 只输出文本，不落 `mastery`）；
- 作业判分写提交记录，但 `track=False` 刻意不写个人进度（`quiz.py:220-224`、`classes.py` 的 `submit_task`）；
- 掌握度只来自"个人测验/练习"，班级作业的成绩不回流；
- 薄弱点补练是"按错题再出一套题"，不是"按课堂表现 + 作业 + 测验综合诊断"。

**扣分**：应用价值再扣 2–3 分；也是 W2 的根因之一。

**怎么改（P1）**：定义一条 `learning_event` 统一事件（来源：课堂发言/作业/测验），所有模块写同一个事件流；诊断 Agent 从事件流取证据。这件事做完，W1、W2、W4 一起解决。

### W5 合规与隐私是"一票否决"级风险

**评委看到**：教师上传的名单里有**教务系统明文密码**；学生是未成年人；数据是本地明文 JSON。

**根因**：

- `server/services/roster.py` 解析 `学号,姓名,密码`，`classes.import_roster()` 把密码哈希后存 `data/students/*.json`，**但导入过程接收的是明文，结果页还会回显初始密码**；
- 没有加密存储（`data/` 全明文 JSON）、没有审计日志、没有数据保留期与删除策略说明、没有未成年人个人信息保护声明；
- 教师 token 存 `localStorage`，有 XSS 泄漏面；默认 HTTP、没有 HTTPS/反代指引；
- 学生 token 是 HMAC 确定性令牌，泄漏一次长期有效（无吊销列表）。

**扣分**：展示/合规 5 分扣到 4 分是客气的；真实评审里，教育赛道评委对"收集未成年人密码"非常敏感，可能直接影响晋级。

**怎么改（P0，赛前必须做姿态）**：

1. **不要收教务密码**。改成：教师导入名单只含学号/姓名 → 系统生成一次性激活码 → 学生首次登录改密；或对接学校统一身份（OAuth/SSO）。
2. 如果必须保留密码导入：**加密落盘（至少 AES/Fernet + 本机密钥）**、导入文件即删、结果页默认打码、加"数据用途/保留期/删除入口"说明。
3. 加审计日志：谁在什么时候导入了多少条、重置了谁的密码。
4. README 增加"合规与隐私"章节，明确"不采集成绩以外的个人信息、数据不出本机、删除方式"。

> 这条不改，答辩很可能被问穿；改了，反而是"我们认真考虑过合规"的加分项。

### W6 技术天花板明显，一追问就到底

**评委看到**：现场 40 人同时用会不会卡？多老师能不能用？数据丢了怎么办？

**根因**：

- 单进程 + JSON 全量读写（`store.py`），虽然加了 mtime 缓存，但仍是 O(N) 扫描；没有数据库、没有索引、没有迁移；
- 事件总线/在线名单/限流都是进程内内存（`services/events.py`、`api/limits.py`），多 worker 即失效；
- 检索 BM25，无向量、无 rerank，资料一多召回质量会掉；
- 无 Docker、无 CI、无结构化日志、无监控、无备份恢复入口（没有 `Dockerfile`、`.github/`、`pyproject.toml`）。

**扣分**：技术维度扣 3–5 分；工程完成度扣 2 分（但对学生项目仍算高）。

**怎么改（P1/P2）**：SQLite（WAL）+ 迁移脚本；Dockerfile + compose；GitHub Actions（ruff/mypy/pytest/build）；结构化日志 + request id；`/api/health` 加版本/队列/延迟指标。**不用全做，做 2 个就能在答辩里说"我们想过规模化"。**

### W7 产品缺口：教师真正天天用的功能还差几块

**评委/教师用户看到**：

- 作业发布后**不能改题**，错一个字要重建整份作业；
- 没有**题库**，好题不能复用；
- 学生没开页面就**收不到通知**（SSE 只在页面打开时有效）；
- 移动端教师表格靠横向滚动（`styles.css` 900px 断点）；
- 无无障碍验证（弹窗无 focus trap）、无国际化。

**扣分**：应用价值扣 2 分；现场教师评委的"会不会用"打分会被拉低。

**怎么改（P2，选 1–2 个）**：题库 + 作业编辑（最刚需）；Web Push 或邮件提醒（故事最好讲）；移动端卡片化。

### W8 商业与团队几乎空白

**评委看到**：没有成本模型、没有定价、没有试点学校、没有竞品分析、没有团队分工、没有软著/论文。

**根因**：README 是技术文档，不是商业计划；没有 `docs/` 商业材料；没有用户/客户证据。

**扣分**：商业 10 分只给 5 分。

**怎么改（P1）**：

- **成本模型**：按每班每月 token 成本估算（判分 + 出题 + 答疑），给出定价区间（如 99–299 元/班/学期）与毛利；
- **竞品对比表**：超星学习通、雨课堂、智谱/豆包教育助手、DeepTutor/OpenMAIC，按"部署成本、数据主权、AI 深度、合规"四维对比，明确"我们赢在哪"；
- **试点**：1 所学校、1 位教师的试用意向书/聊天记录截图，比 10 页 PPT 有用；
- **团队**：如果是单人，补一个设计/商科队友；列出分工与投入时间。

## 四、分项深评

### 4.1 创新性（15/25）

| 加分项 | 现状 |
| --- | --- |
| 组合式创新 | ✅ 把个性化辅导 + 课堂生成 + 作业闭环合成单进程应用，取舍清楚 |
| 零依赖报告 | ✅ 手写 CSS/SVG 图表，单文件离线可打印，是真正的"工程巧思" |
| 实时层抽象 | ✅ 事件只发"变了"，断线重连即补偿，设计克制 |
| 演示模式 | ✅ 无 Key 可跑完整流程，机房场景是刚需 |
| 新方法/新范式 | ❌ 没有 |
| 与上游差异 | ⚠️ 是"重写 + 整合"，不是"超越" |

**评委原话模拟**："做得不错，但这些能力 DeepTutor 和 OpenMAIC 都有，你的增量是什么？"——目前只能答"单进程、易部署、中文课堂场景"，撑不起"创新"。

### 4.2 Agent / AI 技术含量（15/25）

| 能力 | 现状 | 评价 |
| --- | --- | --- |
| 多智能体编排 | 主持人 1 次 JSON + 角色串行流式 | 是"角色扮演"，不是"Agent 协作" |
| 工具调用 | 无 | 缺 |
| 记忆 | 最近 10 条对话 | 无长期记忆/检索记忆 |
| 规划-执行-反思 | 只有"规划一次" | 无 observe/revise |
| RAG | BM25 分块 | 可用，但无向量/rerank/引用定位 |
| 判分 | LLM + 关键词回退 + 注入防护 | 这块做得最好，有工程安全意识 |
| 可观测 | 无 trace | 答辩无法展示"Agent 想了什么" |

### 4.3 完成度与工程质量（17/20）

- 53 个接口、37 个 pytest、4 个冒烟脚本、`api_audit` 0 缺失、实时 + 文件批改 + 名单登录全部走通——这在学生项目里是**前 10%** 的水平。
- 扣分：无 Docker/CI/lint/类型检查、无结构化日志、Python 依赖无 lock、单进程存储。
- 加分：README 写得比很多商业项目好；错误提示中文可读；演示模式诚实标注。

### 4.4 应用价值与效果证据（10/15）

- 痛点真实：教师出题、批改、学情统计确实耗时；课堂互动与作业闭环是刚需。
- 但：**没有一所学校、一个班、一个学生的真实使用数据**；没有"省了多少时间/提了多少分"的数字。
- 评委对"我认为有用"不买账，对"我测过，N=40，提升 12%"才买账。

### 4.5 商业与可持续（5/10）

- 缺成本模型、定价、渠道、客户、壁垒。
- 唯一可讲的壁垒是"校本数据 + 本地部署 + 合规"，但目前没有把它讲成壁垒。

### 4.6 展示 / 合规 / 团队（4/5）

- 文档与代码可读性强，演示模式是加分项。
- 扣分：截图是 v1.2 时期（`docs/*.png` 停留在 2026-10-25，早于 v1.4 文件作业与 v1.5 名单登录）；没有 3 分钟视频、没有 10 页 PPT、没有架构图；合规是硬伤。

| 13 | 多模态（图片题/手写 OCR）或语音 | 课堂真实场景 |
| 14 | 多教师/教研组 + 权限 | 从单机工具到校级产品 |
| 15 | 论文/专利/软著 + 校外试点 | 区域赛决赛的硬通货 |

## 六、答辩会被问到的 12 个问题（附回答要点）

1. **"你的 Agent 和普通 prompt 链有什么区别？"**
   → 现场展示工具调用 trace：Agent 自己决定查掌握度、查错题、生成补练、写报告；失败会重试/换工具。
2. **"多智能体是真的协作吗？"**
   → 承认目前是"主持人编排 + 角色发言"，下一步是共享黑板 + 互评；把"已做/在做/计划"分清楚，比硬吹好。
3. **"效果怎么证明？"**
   → 判分一致性（r=0.8x）、批改耗时下降（x 分钟/份）、前后测 gain；样本小就说样本小。
4. **"和 DeepTutor / OpenMAIC / 学习通比，你的增量？"**
   → 单进程零基础设施、本地数据主权、中文课堂闭环、演示模式可离线；不要正面拼功能数量。
5. **"学生教务密码你怎么处理？"**
   → 已改为一次性激活码/不落明文；如保留，加密 + 审计 + 保留期 + 删除入口。
6. **"40 人同时交卷会不会挂？"**
   → 给压测数字（哪怕 40 并发 P95）；承认单进程边界，给 SQLite/Redis 路线。
7. **"老师为什么不用现成的？"**
   → 数据不出校、可按班级定制、AI 判分可复核、成本可控；给试点教师原话。
8. **"商业化怎么赚钱？"**
   → 每班每学期定价 + token 成本 + 毛利；先校内试点，再区域复制。
9. **"AI 判错了怎么办？"**
   → 教师复核 + 改分留痕 + 异常分降级 + 待复核标记；这正是 v1.4 已做的。
10. **"你的数据从哪来？"**
    → 校本资料 + 教师出题 + 学生作答；强调授权与脱敏。
11. **"团队怎么分工？"**
    → 明确谁做后端/前端/教研/商业；单人就说单人 + 导师/外援。
12. **"如果给你 10 万，你先做什么？"**
    → 先做 3 所学校试点 + 合规 + 题库，而不是加功能；这题考的是判断力。

## 七、参赛材料改造清单

### 7.1 10 页 PPT 结构（建议）

1. 封面：一句话定位（"给中国课堂的本地化 AI 教学 Agent"）
2. 痛点：教师 3 个耗时场景（出题、批改、学情）+ 一张真实访谈截图
3. 方案：一张架构图（学生端/教师端/Agent 层/数据层）
4. 演示：3 张关键截图（课堂生成、文件批改、诊断报告）
5. Agent 技术：工具调用 trace 图 + 与普通 prompt 链对比
6. 效果：判分一致性、耗时、前后测（一张图）
7. 差异化：与 4 个竞品的四维对比表
8. 合规：数据不出校、密码不落明文、未成年人保护
9. 商业：成本/定价/试点/推广路径
10. 团队与路线图：分工、里程碑、软著/论文

### 7.2 3 分钟视频脚本

- 0:00–0:20 痛点（教师深夜批作业的镜头/字幕）
- 0:20–0:50 教师建班、导入名单、发文件作业
- 0:50–1:30 学生提交 → AI 初评 → 教师复核改分
- 1:30–2:20 Agent 诊断报告（重点：工具调用与证据链）
- 2:20–2:50 效果数字 + 合规承诺
- 2:50–3:00 团队与愿景

### 7.3 演示兜底

- 用**演示模式**做现场兜底（无网也能跑），但要提前说明"这是演示数据"，别让评委误以为是真实模型输出。
- 准备 2 个浏览器窗口（教师/学生）+ 1 个手机热点，避免校园网故障。

### 7.4 查新与知识产权

- 做一次简单查新（知网/Google Scholar：AI 作业批改、课堂 Agent、掌握度），列出 3 篇最接近的工作与差异；
- 申请软著（代码量足够）；有条件挂导师/实验室。

## 十一、给作者的最后三句话

1. **不要再用"功能多"证明自己。** 评委记不住 20 个功能，只记得住"一句话 + 一个数字 + 一个现场演示"。

3. **补一张效果图，胜过补十个页面。** 你已经有能力把东西做完整了，现在缺的是"证明它值得被做出来"。
